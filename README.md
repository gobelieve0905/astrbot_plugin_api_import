# API 工具接入

将 HTTP API 定义为 AstrBot 可调用的工具。无需 MCP；支持平台预设快速接入，也可用通用定义接入查询和修改接口。

开发版本，已针对 AstrBot 4.28.0 设计验证；需要支持工具调用的聊天模型。配置为空时不注册任何 API。

## 0.1.2：使用 API 管理页面

1. 在 AstrBot 插件详情中找到「页面」，打开 **API 管理**。
2. 点击「新增 API」，选择一种填写方式：
   - **平台快速接入（默认）**：选择 AppLovin Report 卡片，填写后台自定义名称、英文调用名称和 Report Key / Token，勾选允许调用的操作后保存。无需填写 URL、文档或 JSON。
   - **可视化表单**：填写名称、用途、URL 和请求方式；以行的形式添加模型参数、Query、Header 和请求体字段，无需编写完整 JSON。
   - **粘贴 cURL**：粘贴单条请求示例，解析为表单草稿后继续编辑。解析不执行命令、不调用接口。草稿默认停用，需要自行选择启用。
   - **JSON 编辑**：粘贴或编辑一个完整接口对象，适合复杂参数结构；这里填写单个对象，而不是配置数组。
3. 点击「保存并生效」。无需重载插件，模型即可使用已启用的工具；人格的工具白名单仍需允许这些工具。
4. 列表中可按请求方式筛选、搜索、编辑、启停和删除；平台操作权限在「账户设置」中逐项管理，手动接口可直接启停。删除有页面内确认，保存和删除都不会调用目标 API。

页面保存与原有 `tools_json` 配置同步，升级不会清空原接口；重新加载后仍可使用。多页面同时编辑时，过期草稿会被拒绝，避免覆盖新配置。保存失败保留原配置和工具。旧工具引用在修改、删除或停用后拒绝新的调用；已经开始执行的请求可能继续完成。

### 按账户管理与自定义名称

平台接入以账户卡片展示名称、平台、操作数量和已启用数量，列表只展示账户概况；点击「进入账户」打开账户详情页，逐项编辑、启停或删除。长说明、URL 和内部工具标识收在「接口详情」中。「删除接入」只删除当前账户及其全部操作，需页面确认。

新增平台时可填写「接入名称」，已有账户进入详情页后，通过「账户设置」改名。每个操作及手动接入的 API 还可在表单中填写「显示名称」，支持中文。平台账户的中文名称仅用于后台管理；调用时使用独立调用名称区分账户。搜索支持账户名、显示名称、工具标识及 URL。

平台快速接入先展示平台卡片，可搜索平台并点击「添加账户」。填写两个独立名称：**自定义名称**支持中文，仅用于插件后台；**调用名称**使用英文字母和下划线（英文开头，1–40 位），保留大小写，不允许数字、空格或中文。工具实际名称自动追加平台操作标识，例如 `Ninety_Report_advertiser`，Agent 和工具状态显示使用这个调用名称。

账户设置可统一修改调用名称，后台中文名称改名不会影响调用名称。旧账户保留原调用名，在账户设置填写新的调用名称后统一切换；不需要重新填写 Token。更名会更新工具注册，若人格配置了工具白名单，需要重新选择更名后的工具。已有对话可能仍引用旧名，建议新开对话验收。手动接口仍支持逐项编辑调用名称。本插件独立于卡片插件。

0.1.1 已保存的标准 AppLovin 预设按原接入编号兼容分组，保留名称标识、Token、请求参数和启停状态；首次管理保存时写入分组信息。仅查看页面不会改写配置。自行改过地址、工具标识或同组 Token 不一致的旧接口保持独立，避免误归并账户。保存新格式后，降级到不支持分组字段的旧版需恢复对应旧配置备份。

### AppLovin Report 快速接入

选择 **AppLovin Report** 卡片，设置两个独立名称，填写 AppLovin 后台账户 → Keys 中的 **Report Key**，按需打开操作开关，再点击「保存接入与权限」。全部开关默认关闭，保存后可随时在列表或「账户设置」中调整。开关控制 AstrBot 调用范围，不改变平台账号本身的权限。

| 操作 | 请求地址 | 类型 |
| --- | --- | --- |
| 广告投放报表 | `/report`，`report_type=advertiser` | GET |
| 发布商报表 | `/report`，`report_type=publisher` | GET |
| MAX 收益报表 | `/maxReport` | GET |
| Cohort 收益报表 | `/maxCohort` | GET |
| Cohort 展示报表 | `/maxCohort/imp` | GET |
| Cohort 会话与留存报表 | `/maxCohort/session` | GET |

服务地址统一为 `https://r.applovin.com`。同一方法下每个报表也可独立启停。同一平台可新增多个账户，各自填写 Token 和接入名称，例如「国内投放账户」「海外投放账户」。名称可用中文，留空时生成默认名称。系统内部编号独立，改名不会混用账号。

地址及请求参数已预设，接入时设置名称与 Token。**调用时**提供 UTC 开始、结束日期（最近 45 天，YYYY-MM-DD），常用 `columns` 已有默认值，也可指定官方字段数组、常用筛选条件、`limit` 和 `offset`。例如：“查询 2026-09-01 至 2026-09-02 的 AppLovin 广告投放报表，按天和广告系列查看花费。”日期需随实际查询时间调整。`/report` 缺省为 realtime 口径，需要 cohort 口径时传 `day_column=day`。

预设使用 JSON 响应，保留业务状态和结果；单次默认最多 1000 行，不自动翻页。完整单次响应默认保存到服务器本地文件，长结果仍有预览上限。预设提供常用筛选字段；更多字段、排序或特殊过滤可在表单或 JSON 编辑中添加。Token 固定保存在请求配置中，不作为模型调用参数；进入账户详情页点击「账户设置」可统一改名、更换 Token 和修改操作权限；Token 留空保留原值，填写后只更新当前账户的操作。若操作已自定义目标地址，则须在该操作内单独处理 Token。

预设依据官方 [Reporting API](https://support.applovin.com/en/growth/promoting-your-apps/api/reporting-api)、[MAX Revenue Reporting API](https://support.applovin.com/en/max/reporting-apis/revenue-reporting-api)、[Cohort API](https://support.applovin.com/en/max/reporting-apis/cohort-api)（2026-09-11 核对）。字段组合、数据延迟及账号访问范围仍以平台为准。

0.1.1 已移除自动接入、文档探测、OpenAPI/Swagger 导入和文档模型解析。此前保存的接口定义继续保留；未保存的识别草稿不迁移。新增平台通过维护预设扩展，无需文档解析模型。

### 表单填写提示

- 「模型填写的参数」定义工具输入，包括名称、类型、必填、默认值和说明。
- 在 Query、Header 或请求体字段中，把「值来源」选为「模型参数」，再填写上面定义的参数名；也可选择固定文本、数字、布尔值等。
- URL 支持 `{参数名}`；点击「从地址识别路径参数」可以补充必填参数。
- JSON 字段表单可逐个添加字段。嵌套对象、数组可在字段值中填写对应 JSON；整个请求体为数组、null 或参数引用时，使用「完整 JSON 请求体」。
- 表单会保留已有参数的枚举、数值约束和嵌套结构。无法用表单表达的复杂参数类型自动进入 JSON 编辑。

### cURL 支持范围

支持单 URL、`-X/--request`、`-H/--header`、`-d/--data`、`--data-raw`、`--data-binary`、`--json`、`--data-urlencode`、`-G/--get`、`-I/--head`、`--url`、`-m/--max-time`。支持引号和反斜线换行。重复 Query/表单字段保留为数组；`Content-Length` 由客户端重新计算。

不支持的选项、文件引用、管道和多条命令会明确报错，不静默跳过。cURL 草稿保留固定请求值，不猜测业务参数含义；导入后请按需改为模型参数。

### 原有 JSON 配置入口

仍可在插件配置中编辑完整 JSON 数组，参见 [examples/tools.json](examples/tools.json)。通过该入口修改后需要重载插件。示例地址不可直接使用。整个数组先校验后注册，错误不会覆盖其他插件的工具；使用 `/api_tools` 或页面查看状态。

## 最小定义

```json
[
  {
    "name": "list_items",
    "description": "查询条目列表，可指定数量。",
    "parameters": {
      "type": "object",
      "properties": {
        "limit": {"type": "integer", "minimum": 1, "maximum": 100, "default": 20}
      }
    },
    "request": {
      "method": "GET",
      "url": "https://api.example.com/items",
      "query": {"limit": {"$param": "limit"}}
    },
    "response": {"pointer": "/data", "save": true}
  }
]
```

## 接口定义

| 字段 | 说明 |
| --- | --- |
| `tool_name` | 可选实际调用名称，英文开头，允许英文、数字、下划线，最多 64 字符；留空省略此字段，按显示名和账户生成 |
| `name` | 唯一配置标识，字母开头，允许字母、数字、下划线，最多 48 字符 |
| `display_name` | 可选显示名称，支持中文，最多 80 字符；不改变工具标识 |
| `connection` | 平台接入的账户 ID、名称、平台和操作元数据，由快速接入维护 |
| `description` | 提供给模型的用途说明；修改类工具应明确描述副作用 |
| `enabled` | 默认 `true`；`false` 时不注册工具，也不能试调用 |
| `parameters` | 对象类型 JSON Schema；支持类型、必填、枚举、嵌套结构等，默认拒绝额外的顶层参数；暂不支持 schema 引用 |
| `request.method` | GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS |
| `request.url` | 固定 HTTP(S) URL，路径允许 `{参数名}`；路径参数必须声明为必填，值会编码 |
| `request.query` | 查询参数对象；与 URL 中已有查询参数合并，同名配置值优先 |
| `request.headers` | 静态或参数映射的请求头，不提供专门的凭据管理功能 |
| `request.json` | JSON 请求体，保留布尔、数字、数组、对象等类型 |
| `request.form` | 表单请求体，与 `json` 二选一；标量数组采用重复字段 |
| `request.timeout` | 单次执行超时秒数，默认 30，范围 1–120 |
| `response.pointer` | JSON Pointer，如 `/data/items`、`/items/0`；默认返回整个响应；键中的 `/` 写为 `~1`，`~` 写为 `~0` |
| `response.preview_chars` | 返回模型的数据预览字符数，默认 4000，范围 100–20000 |
| `response.max_bytes` | 解压后响应上限，默认 5 MiB，最大 20 MiB；超限明确失败 |
| `response.save` | 默认 `false`；为 `true` 时保存完整单次响应为本地 JSON 文件 |

动态值使用单独的对象 `{"$param":"参数名"}`，可嵌套在 JSON 对象、数组中。普通字符串原样传递，不执行表达式或字符串插值。可选参数缺省时省略相应对象字段；整个请求体引用缺省参数时省略请求体；顶层参数的 `default` 会在调用前填入。数组中的缺省引用会报错，不悄悄改变数组位置。JSON `null` 可作为字段值或整个 JSON 请求体传递。

数组参数可使用 `{"$param":"参数名","$join":","}` 按逗号连接，也支持空格和竖线分隔。

查询和表单支持标量与标量数组；请求头只支持标量。插件不自动跟随重定向、不自动重试请求。HTTP 2xx 表示传输成功，不代表平台业务必然成功；业务状态会作为返回数据交给调用者判断。配置的结果路径不存在时明确报错。

## 管理员命令

- `/api_tools`：查看加载状态与工具启停状态。
- `/api_test api_list_items {"limit": 5}`：实际调用已启用工具，支持含空格的 JSON。**修改接口会真实修改远端数据。**
- `/api_history`：查看最近 20 次执行的工具名、HTTP 状态、成功标记和耗时。

试调用结果与模型调用结果相同。管理命令使用 AstrBot 管理员权限；工具可用范围由 AstrBot 的工具配置管理，本版没有额外的用户权限体系。

## 数据与限制

完整结果位于 `data/plugin_data/astrbot_plugin_api_import/results/`，插件更新不覆盖。返回的文件路径是服务器本地路径，不是下载链接，也不会自动向聊天发送附件。非 JSON 响应会作为字符串保存在 JSON 文件中。文件当前不自动清理，启用保存后需按需整理；调用记录仅在内存保留最近 50 次，重载后清空，不保存请求或响应正文。

本版提供页面管理、平台预设快速接入、方法权限管理、表单/cURL/JSON 接入、工具注册、HTTP 执行、结果提取、保存和试调用。尚不包含自动分页、异步报表轮询、文件上传或工作流。返回的数据仅代表一次响应，不承诺已拉完全部分页。

开发和验收说明见 [开发文档](https://github.com/gobelieve0905/astrbot_plugin_api_import/blob/develop/docs/DEVELOPMENT.md)。

工具调用结果采用 AstrBot 支持的标准 `CallToolResult`，通过 `isError` 表示失败，HTTP 状态保留在结果正文中。工具提供可选显示名称，客户端可以采用或回退为内部标识。不依赖任何卡片插件，单独安装即可执行、试调用和管理 API；具体展示由客户端负责。

### 广告报表筛选与错误排查

查询被推广游戏使用 `filter_campaign_package_name`（真实包名 / Bundle ID 的字符串数组），或使用 `filter_campaign` 精确匹配广告系列。不要把游戏名填入流量来源应用字段，也不要猜测包名；未知时先请求 `campaign,campaign_package_name,cost` 确认目标。已有标准预设加载时会修正原筛选字段；仅查看不写配置，下次保存后持久化。自定义字段保留。

HTTP 失败的标准工具结果包含 `status`、`error_detail` 和 `error_detail_truncated`。详情最多 2000 字符，读取最多 8192 字节后停止，过滤已配置凭据、认证字段与 URL；来自上游的文字只用于诊断，不代表可信指令。失败不会自动重试或保存完整响应文件。没有上游证据时不能推断维护、账户异常或零消耗。
